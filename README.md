# AyurRasoi (prototype)

A local prototype Ayurvedic recipe app. Runs entirely on your machine — nothing is deployed publicly, and nothing costs money.

## Running it

The app starts automatically when Claude opens it in the Browser pane. To run it yourself from a terminal:

```
node server/index.js
```

Then open http://localhost:5173 in a browser.

## Everything here is free — no API keys required

Earlier versions of this prototype used paid APIs (Anthropic Claude for recipe extraction, Runway for AI video). Both have been replaced with free alternatives:

### "Add recipe" — now a free rule-based parser, not AI

Since there's no paid language model doing the understanding anymore, the app looks for **labeled sections** instead of parsing arbitrary prose. Format pasted text like this for best results:

```
Name: Ginger tea for sore throat
Ingredients:
- Ginger
- Water
- Honey
Steps:
1. Boil sliced ginger in water for 10 minutes.
2. Add honey once warm.
3. Drink twice a day.
Source: Charaka Samhita
```

It'll still work with less structure (e.g. a single "Name: description" sentence), but the more clearly labeled, the better it parses. If it can't find ingredients or steps, it tells you so and suggests reformatting — it won't silently produce a broken recipe.

### 16 languages — now via the free Lingva Translate service

No key needed. Lingva Translate is a free, open-source, keyless front end for Google Translate's engine. The language switcher (a dropdown in the header, not a toggle anymore) covers: English, Hindi, Bengali, Marathi, Tamil, Telugu, Kannada, Odia, Gujarati, Punjabi, French, Spanish, German, Russian, Mandarin, and Cantonese.

A few things worth knowing:

- **Cantonese is a labeled exception, but only for text.** Google Translate's text engine (which Lingva wraps) has no distinct Cantonese target — only Mandarin ("zh"). So the Cantonese option shows the same written text as Mandarin. The spoken narration is different, though — see the audio section below.
- **The full 7-recipe library × 16 languages was generated by a one-time script** (`server/scripts/generateTranslations.js`), not by hand. It's safe to re-run — it only fills in languages that are still missing, so a partial or interrupted run just resumes. If you add a language, edit `server/languages.js` and `server/data/uiText.en.json`, then re-run the script.
- **It depends on public instances staying up**, and they do get rate-limited under heavy use (you may see some `500` errors in the script's output — that's normal, just re-run it). The app tries `lingva.ml` first, then a backup, and you can point it at a different instance via `LINGVA_URL` in `server/.env`.
- **If translation fails for a language when adding a new recipe live** (not via the migration script), that recipe still saves — the affected language's fields just fall back to a copy of the English text, with a visible note on the recipe telling you which languages didn't come through, so you can regenerate later.
- **Section headers in "Add recipe" must stay in English** (`Name:`, `Ingredients:`, `Steps:`, `Source:`, `Safety:`) no matter which language you're writing the recipe content in — the free parser only recognizes those English keywords. The content after each header can be in any language.

### Audio narration — real generated voice, not the device's built-in voices

The "Guided audio walkthrough" used to rely on the browser's Web Speech API, which only works if your operating system happens to have a voice pack installed for that language (this machine, for instance, only had English voices — Hindi narration would have come out in an English accent reading Hindi text). That's gone now.

Narration is generated server-side using Google Translate's free public text-to-speech endpoint (the same one the well-known `gTTS` Python library wraps) and served back as real `.mp3` files — so it sounds the same for every listener regardless of what's installed on their device.

How it works:

- **Generated once, cached forever.** The first time anyone hits Play on a given recipe in a given language, the server generates the audio and saves it under `server/audio/<recipe-id>/<language>/`. Every play after that is instant — it's just a static file.
- **Cantonese genuinely sounds like Cantonese.** Even though Cantonese shares Mandarin's written text (see above), the free TTS engine does have a distinct Cantonese voice — verified by comparing the actual audio output, not just assumed.
- **Odia has no voice at all.** The free TTS engine doesn't support Odia — the app detects this and shows "voice narration isn't available for this language yet" instead of pretending to play something. Everything else (16 minus Odia = 15 languages) works.
- **Long text gets automatically split and stitched.** The free endpoint caps out around 200 characters per request, so longer sentences are chunked at sentence/word boundaries and the resulting audio clips are concatenated — invisible to you, just a slightly longer first-load.
- **No API key, no cost, same free-service caveat as translation**: it's a public endpoint that can occasionally return errors under heavy use; the app surfaces a clear error rather than failing silently, and retrying usually works.

### Prep visual — now a free animated icon strip instead of AI video

No AI video generation at all anymore — that requires a paid service no matter which provider you use. Instead, each recipe shows its ingredient icons in a small animated strip, and the icon matching the ingredient mentioned in the current step gets highlighted while the audio walkthrough plays. It's a much lower-fidelity substitute for a real video, but it's genuinely free forever and needs no account, no billing, and no per-use cost.

If you ever want real filmed video for a recipe, drop an actual video file's path into that recipe's `videoUrl` field in `server/data/recipes.json` — the player will pick it up automatically instead of showing the icon strip.

## Where things live

- `public/` — the frontend (what you see in the browser)
- `server/` — the backend (recipe storage, the free parser, translation calls)
- `server/data/recipes.json` — the actual recipe database. Back this up if you add recipes you care about.
- `server/data/uiText.json` — generated UI text for all 16 languages (source of truth is `uiText.en.json` + the generation scripts)
- `server/audio/` — cached generated narration `.mp3` files, created on first play per recipe/language

## Sharing it with test users (temporary public link)

`tools/cloudflared.exe` is a free tunnel tool from Cloudflare — no account needed. It exposes your locally-running app at a temporary public URL like `https://random-words.trycloudflare.com`, so testers on any device/network can open it in a browser.

**To start a share link:**

```
tools\cloudflared.exe tunnel --url http://localhost:5173
```

It prints a `https://....trycloudflare.com` URL after a few seconds — that's what you send to testers.

**Things to know about this approach:**

- **The link only works while both `node server/index.js` and this `cloudflared` command are running on your computer.** Close either one (or put your laptop to sleep) and the link goes down.
- **The link changes every time you restart the tunnel.** If you need a stable, unchanging link, that requires a real deployment (a free Cloudflare account with a named tunnel, or hosting on Render/Railway) rather than this quick option.
- **There's no login and no access control.** Anyone who has the link can use the full app, including adding recipes — it's meant for a small group of trusted testers you send the link to directly, not for posting publicly.
- **Feedback on data they add**: since `server/data/recipes.json` is a single shared file, if multiple testers add recipes at the same time, they're all editing the same file — fine for casual testing, but worth knowing.
- **The free tier caps at 200 concurrent requests** — no realistic concern for a small test group.

When you're done testing, close the `cloudflared` window/process to shut the tunnel down (or just close your terminal/computer).

## Safety note

Every recipe — whether hand-written or parsed from pasted text — is a **draft**. None of this has been reviewed by a qualified Ayurvedic practitioner. Don't treat anything in this app as medical advice until that review has happened.
